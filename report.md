Таблиця Network (сторінка http://127.0.0.1:5500/index.html, перезавантаження F5)

| Запит (Name) | Метод | Статус | Тип        | Розмір  |
|--------------|-------|--------|------------|---------|
| index.html   | GET   | 200    | document   | 2,1 kB  |
| logo.png     | GET   | 200    | png        | 7,7 kB  |
| ws           | GET   | 101    | websocket  | 0 B     |

Примітка: при повторному F5 logo.png може мати статус 304 Not Modified — браузер бере картинку з кешу, бо сервер підтвердив, що вона не змінилась. Запит ws — це з'єднання Live Server для автоматичного оновлення сторінки.

Headers запиту index.html:
Request URL: http://127.0.0.1:5500/index.html
Request Method: GET
Status Code: 200 OK
Content-Type: text/html; charset=UTF-8

Помилка 404: коли в src написав images/logo1.png, у Network з'явився червоний запит logo1.png зі статусом 404 Not Found, а на сторінці замість картинки показався текст «Логотип TaskBoard» з атрибута alt. Після виправлення на images/logo.png картинка знову завантажилась зі статусом 200.

Elements: змінив текст заголовка h1 прямо в DevTools — на сторінці він змінився, але файл index.html залишився без змін. Після F5 повернувся старий текст «TaskBoard».

Console:
document.title повернула "TaskBoard" — це текст із тегу <title>.
document.body.style.background = "lightyellow" зробила фон сторінки світло-жовтим.
Після F5 фон знову став білим, тобто зміна не збереглась.


Відповіді на запитання

1. Яка адреса сторінки в браузері? З яких частин вона складається?
Адреса: http://127.0.0.1:5500/index.html. Тут http — протокол, 127.0.0.1 — IP-адреса мого ж комп'ютера (localhost), 5500 — порт, на якому працює Live Server, а /index.html — шлях до файлу на сервері.

2. Скільки запитів зробив браузер при завантаженні сторінки і чому саме стільки?
Браузер зробив 2 основні запити: спочатку index.html, а потім, прочитавши в HTML тег <img>, окремо запросив images/logo.png. Ще є третє з'єднання ws — його відкриває скрипт, який Live Server додає в сторінку, щоб вона оновлювалась сама після Ctrl+S. Кожен файл, на який посилається сторінка, браузер завантажує окремим запитом.

3. Що відбулось, коли ти поставив неправильний шлях до зображення?
Сервер не знайшов файл logo1.png і повернув статус 404 Not Found, у Network цей запит став червоним. На сторінці замість картинки з'явився текст з атрибута alt — «Логотип TaskBoard».

4. Чому зміни, зроблені через DevTools, зникли після F5?
DevTools змінює тільки копію сторінки (DOM), яка зараз є в пам'яті браузера, а не сам файл index.html на диску. При F5 браузер знову завантажує файл із сервера, тому всі зміни з Elements і Console пропадають.

5. Хто в цій схемі клієнт, а хто сервер?
Клієнт — браузер, який надсилає запити і показує сторінку. Сервер — Live Server, запущений на моєму комп'ютері за адресою 127.0.0.1:5500, який віддає файли index.html і logo.png у відповідь на запити.


Додаткове завдання

1. Створив about.html і зробив посилання між сторінками: на index.html є посилання «Про проєкт», а на about.html — «На головну».

2. Сторінка http://127.0.0.1:5500/qwerty: Live Server повернув статус 404 Not Found і просту сторінку з текстом «Cannot GET /qwerty», бо такого файлу в папці проєкту немає.

3. curl.exe -I http://127.0.0.1:5500/index.html повернув:
HTTP/1.1 200 OK
Accept-Ranges: bytes
Cache-Control: public, max-age=0
Last-Modified: Wed, 28 Oct 2026 21:03:54 GMT
ETag: W/"26a-1a184539cc3"
Content-Type: text/html; charset=UTF-8
Content-Length: 618
Connection: keep-alive

Заголовки ті самі, що в DevTools: статус 200 OK і Content-Type text/html; charset=UTF-8. Різниця в тому, що curl -I робить запит HEAD (тільки заголовки, без тіла) і показує Content-Length 618 байт — це реальний розмір файлу. А браузер у DevTools отримує сторінку розміром близько 2,1 kB, бо Live Server при звичайному GET дописує в HTML свій скрипт для автооновлення.
